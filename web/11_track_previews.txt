● Flash removed: dropped .item.fired/@keyframes fired from index.html and the
  class-toggle line in web/launcher.js:559 (plus the now-dead entry in the
  reduced-motion block).

  On preview slowness — the cost is buildStage() in web/preview.js:290
  re-running gs.loadstage (full geometry construction) plus a whole renderer
  pass on every keypress, so the options are: debounce arrow input so only the
  settled stage builds, cache each stage's finished preview as an ImageBitmap
  and blit it on revisit, or precompute preview images offline and ship them as
  assets.

  The superimposition is a separate bug from the same path — Graphics2D.end()
  (web/graphics.js:590) returns without clearing when a frame emits no geometry,
  so a failed/empty render leaves the previous stage's image on the canvas
  under the next one. Say the word and I'll fix that and whichever slowness
  option you want.

● Yes — the preview canvas is 1600×900 (index.html:282) for a ~200px thumbnail,
  so dropping it to display size cuts the raster/fill cost, and since the images
  are that small you can also warm the whole set during menu idle time (build
  each stage once in the background, keep the bitmaps) so a live load is never
  more than a blit.
